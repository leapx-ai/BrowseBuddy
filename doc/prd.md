## 1. 项目概述(BrowseBuddy)

### 1.1 产品背景

浏览器历史记录是用户网络行为的重要数据，但原生浏览器的历史管理功能通常较为基础。用户需要更强大、更灵活的工具来管理自己的浏览历史，包括清理、分类、分析和隐私保护等功能。

### 1.2 产品定位

一款专注于浏览器历史记录管理的增强型插件，提供专业级的历史记录管理功能，同时高度重视用户隐私保护，所有数据本地处理，不上传云端。

### 1.3 目标用户

- 注重隐私保护的用户
- 需要清理特定历史记录的用户
- 希望分析自己浏览行为习惯的用户
- 需要管理大量历史记录的研究人员、分析师
- 希望隐藏某些网站访问记录的用户

### 1.4 核心价值主张

1. **隐私安全**：所有数据本地处理，不上传云端
2. **高效管理**：提供批量操作和智能分类
3. **深度洞察**：提供详细的统计分析
4. **灵活控制**：精细化控制历史记录保留策略

## 3. 非功能需求

### 3.1 隐私与安全

1. **本地存储原则**：所有历史记录数据仅存储在用户本地设备
2. **无云端同步**：不提供云端同步功能，避免数据泄露风险
3. **权限最小化**：仅请求必要权限，安装时明确说明权限用途
4. **开源可选**：考虑提供开源版本供技术用户审查代码
5. **隐私政策**：提供明确、简洁的隐私政策，承诺数据本地化

### 3.2 性能要求

1. **响应时间**：普通操作响应时间<200ms，批量操作<2秒
2. **内存占用**：插件内存占用<100MB（万条记录规模）
3. **加载速度**：插件界面加载时间<1秒
4. **数据量支持**：支持至少10万条历史记录的高效管理

### 3.3 兼容性要求

1. **浏览器支持**：优先支持Chrome、Firefox、Edge
2. **版本支持**：支持最近3个主要版本的浏览器
3. **操作系统**：支持Windows、macOS、Linux主流版本

### 3.4 用户体验

1. **界面简洁**：界面设计简洁直观，避免过度复杂
2. **操作流畅**：提供流畅的交互体验和动画过渡
3. **帮助文档**：提供详细的使用帮助和常见问题解答
4. **多语言支持**：至少支持中英文界面

## 附录D：黑名单功能技术实现

### D.1 主域名提取算法
```
输入: URL 或 hostname
输出: 主域名

1. 从 URL 提取 hostname（去除协议、路径）
2. 将 hostname 按 "." 分割为数组
3. 判断是否为特殊 TLD（.com.cn, .co.uk 等）
   - 是：返回最后三部分（如 example.com.cn）
   - 否：返回最后两部分（如 example.com）
```

### D.2 黑名单匹配逻辑
```
用户访问 URL: https://www.blog.example.com/article
                ↓
提取主域名: example.com
                ↓
与黑名单比对: [example.com, google.com, ...]
                ↓
匹配成功 → 调用 chrome.history.deleteUrl() 删除该记录
        → 显示 3 秒 🔒 徽章提示
```

### D.3 数据结构设计
```typescript
interface BlacklistEntry {
  id: string;           // 唯一标识
  pattern: string;      // 主域名（如 "example.com"）
  type: 'exact';        // 固定为精确匹配（简化设计）
  enabled: boolean;     // 是否启用
  createdAt: number;    // 创建时间戳
}
```

### D.4 用户交互设计
- **快捷添加**：显示"添加当前页面 (example.com)"按钮，一键添加
- **手动添加**：输入任意 URL，实时显示提取的主域名，确认后添加
- **列表管理**：显示主域名，支持启用/禁用切换和删除
